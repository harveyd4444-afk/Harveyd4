03

AI agents in detail

Each agent is backed by Gemini 3.1 Flash Lite at temperature 0 for deterministic output, a structured output parser that enforces a strict JSON schema, and a fallback Gemini "Fixer" model shared across all three parsers to auto-repair malformed JSON.

1

Website Verification Agent

Given only a company name, company number, registered address, and SIC codes from Companies House, this agent uses Serper web search to find the company's official website. It looks for multiple independent signals — name match, location, content consistency — and returns a confidence score. Critically, it refuses to guess: if no reliable website can be confirmed, it returns website_verified: false rather than fabricating a URL. Hard rule: the company's name must actually appear on the candidate site.

Gemini Flash Lite Serper search Gate: ≥80 confidence
2

Company Research Agent

Receives the verified website and Companies House data, then conducts a structured deep-dive: industry classification, company description, products and services, target audience, business model, observable social profiles, and current content activity. Crucially, it is explicitly instructed not to evaluate Vedit Media fit at this stage — keeping the research factual and the scoring objective. Returns a research_confidence score with reasoning.

Gemini Flash Lite Web browsing Gate: parseable result
3

Fit Evaluation Agent

The final scoring agent receives both the company research and a live scrape of Vedit Media's own website, so the ICP is always current — not hardcoded into the prompt. It evaluates commercial capability, content gaps, observable marketing signals, and audience fit, and outputs a scored verdict (0–100) with reasoning, recommended services, content opportunities, commercial signals, and risks. Only companies scoring ≥65 with proceed_to_pdf: true are saved.

Gemini Flash Lite Live site context Gate: fit ≥65

05

Key design decisions

ICP sourced live, not hardcoded

Agent 3 scrapes Vedit Media's live website at run time and uses that as the scoring context. This means the ideal client profile updates automatically as Vedit's positioning evolves — no workflow edits needed.

Staged gating with graceful fallback

Rather than a single pass-or-fail at the end, each phase has its own quality gate. Companies that fail verification or research are flagged for manual review and the loop continues immediately — no whole-batch blocking.

Temperature 0 across all agents

All three Gemini models run at temperature 0. Lead qualification requires consistent, reproducible scoring — not creative variation. The same company should score the same on every run.

Separation of research and scoring

Agent 2 is explicitly prohibited from evaluating Vedit fit. Keeping factual research separate from scoring prevents confirmation bias — the scoring agent sees raw facts, not a pre-spun narrative.

Shared Fixer model for JSON repair

A single Gemini "Fixer" model is connected to all three structured output parsers. When an agent's response is malformed JSON, the Fixer repairs it automatically before the pipeline errors — reducing failed runs significantly.

Conservative scoring by design

Agent 3's prompt explicitly instructs it to score conservatively and return a low score when evidence is thin. This keeps the prospect list genuinely high quality rather than inflated — better to miss a few than to flood the pipeline with weak leads.

Full JSON audit trail

Every agent's complete raw output is written to its own column in Sheets. This means scoring decisions are always explainable and the data remains reusable — Agent 3's JSON feeds directly into the downstream proposal PDF workflow.
